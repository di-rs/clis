# Biggie

`biggie` generates reproducible ASCII text for CLI benchmarks and test cases.
By default each line contains 7–14 space-separated words, each 2–11 ASCII
alphanumeric characters long. File destinations are created or truncated.

## Usage and flags

From the workspace root, with a disposable destination:

```sh
cargo run --locked -p biggie -- --seed 42 -n 100 biggie-example.txt
```

| Argument | Behavior |
| --- | --- |
| `FILE` | Destination, default `out.txt`. `-` streams data to stdout; use `./-` for a file named `-`. |
| `-n`, `--lines LINES` | Record count as an unsigned 64-bit integer, default 100,000. Zero creates empty output. |
| `--seed U64` | Unsigned 64-bit seed, including zero. Omitted: fresh randomness. |
| `--words-per-line RANGE` | Fixed `N` or inclusive `MIN..=MAX`, default `7..=14`. Zero words produces a blank record. |
| `--word-length RANGE` | Fixed `N` or inclusive `MIN..=MAX`, default `2..=11`. Lengths are positive ASCII byte counts. |
| `--line-ending lf\|crlf` | Record terminator, default `lf`, independent of the host OS. |
| `--no-final-newline` | Omit the final record's terminator; earlier records retain the selected line ending. |
| `-h`, `--help` | Show help. |
| `-V`, `--version` | Show version. |
| `--log-level LEVEL` | `off`, `error`, `warn`, `info`, `debug`, `trace`; default off. |

Explicit `--log-level` overrides `CLIS_LOG_LEVEL`, which overrides the default off.
Invalid effective settings fail during Clap parsing, before creating data.
The shared setup has no `-v`/`-q` aliases, file/JSON options, or timing switch.
See the [shared contract](../docs/observability.md).

Ranges use unsigned 32-bit integers with minimum ≤ maximum. Equal endpoints are
valid; open-ended, descending, and exclusive `MIN..MAX` ranges are rejected.
Counts and lengths are sampled uniformly from their inclusive ranges. Options
are validated before creating or truncating the destination, even with zero records.

For two fixed-width records on stdout, using CRLF and no final terminator:

```sh
cargo run --locked -p biggie -- - --seed 42 -n 2 \
  --words-per-line 3 --word-length 4 --line-ending crlf --no-final-newline
```

Each record has 14 content bytes (12 letters/digits and two spaces), making this
output exactly 30 bytes. The line count is a record count, not a newline count:
three blank records without a final terminator produce only two terminators;
one blank unterminated record and zero records both produce empty bytes.

File output retains the completion message on stdout. With `FILE=-`, stdout
contains only generated bytes and there is no completion message. No destination
file is created in that mode. Diagnostics use plain text on stderr at either
destination. Successful generation emits an info event through `log`;
debug records the requested count and trace records completion. At debug/trace,
`command`, `generate`, and `flush` spans emit built-in close records with timestamps
and busy/idle duration strings. Generation records completed counts only on success.
There are no per-line or input-content logs.

Errors always go to stderr once, prefixed with the name from Clap. Parsing errors
exit 2; operation, setup, or reported write/flush errors exit 1. Success exits 0
after explicit data/diagnostic flushing. An error can leave a partial data file.
Backtraces are independent of verbosity; the concise reporter displays causes.

## Rust library

Use `biggie = { path = "../clis/biggie" }` from a consumer beside this checkout:

```rust
use biggie::{GenerationOptions, generate};

let options = GenerationOptions {
    lines: 2,
    seed: Some(42),
    words_per_line: 3..=3,
    word_length: 4..=4,
    ..GenerationOptions::default()
};
let mut output = Vec::new();
generate(&mut output, &options)?;
# Ok::<(), std::io::Error>(())
```

The [operation](src/lib.rs) accepts a writer and typed `GenerationOptions`, returning
`io::Result<()>`. `LineEnding::Lf` and `LineEnding::CrLf` select terminators;
`final_newline` defaults to true. Invalid ranges return `InvalidInput` before any
write. `gen_random_lines(writer, count)` remains available with unseeded defaults.

The top-level operation initializes one `StdRng` from the seed (or fresh randomness).
Internal helpers borrow that RNG; they neither receive a seed nor initialize their
own generators. Calls have independent RNG state. Output streams through an 8 KiB
word buffer, so library scratch memory does not grow with the record count or word
length. Wrap file writers in `BufWriter` for efficient small writes, as the CLI does.
The library does not flush the writer, parse arguments, configure tracing or use
global streams. Write errors preserve already written bytes. Callers may supply
their own subscriber.

## Reproducibility and benchmark inputs

The same seed, options, and build on the same platform produce identical bytes in
files and on stdout. Changing only the destination, logging, or line terminators
does not change the generated words. Without a seed, output is not reproducible.
`StdRng` and sampling algorithms may change across dependency versions or platforms;
there is no promise of byte stability across upgrades.

Record the generator revision, `Cargo.lock`, platform, full command including seed,
and checksum. Generate inputs once outside timed runs and reuse those exact files
for every candidate/reference. Preserve input files when long-term replay matters.
See the [benchmark procedure](../docs/benchmarking.md). Large datasets belong under
`target/` or another disposable directory, not in tracked regression fixtures.

## Requirements for further data shapes

The implemented controls cover reproducibility, scale, short/long records, empty
inputs, blank lines, file/pipe access, and line-ending boundaries. The following
requirements come from the current CLI contracts and tests; they are follow-up
work, not implemented controls. Future CLIs should add cases to this matrix
when their input contracts become known.

| Priority | Data condition | Consumers and acceptance criteria |
| --- | --- | --- |
| Next | Unicode and whitespace alphabets | `wcr`, `cutr`, `headr`, `tailr`, `catr`: specify byte vs scalar lengths; include combining marks, wide characters, emoji, tabs, and Unicode whitespace without normalization. |
| Next | Controlled repeated records | `uniqr`: exact adjacent run lengths, nonadjacent duplicates, and blank runs; generated counts must be independently predictable. |
| Next | Known matching/nonmatching records | `grepr`: explicit literals or templates, exact match counts/positions, and case variants; control accidental matches in background text. |
| Next | Delimited fields | `cutr`: fixed field counts, tab/comma separators, empty fields, quoted delimiters and escaped quotes; distinguish plain delimited text from CSV. |
| Later | Raw bytes and exact byte budgets | Byte-oriented `headr`/`tailr` and future tools: NUL, invalid UTF-8, ANSI/control bytes, exact sizes around I/O boundaries; define how byte limits interact with record limits and partial terminators. |
| Later | Sorted, overlapping paired inputs | `commr` and future sort/join tools: explicit byte/scalar ordering, exact shared/unique counts, duplicates, and a memory policy for sorting. Do not assume locale collation. |
| Separate scope | Filesystem fixture trees | `findr`, `lsr`, `mkdirr`, `touchr`: deterministic paths, depths, counts, symlinks, modes, timestamps and non-UTF-8 names in a temporary root; platform-specific cases need separate contracts. |

Each addition must use the same top-level RNG ownership, deterministic parameters,
direct-library validation, byte-level assertions, and bounded memory or documented
resource limits. Cross-version byte-stable generation would require a versioned
algorithm and fixture format; it is a separate compatibility commitment.

## Limits and evidence

Variable-length records do not specify an exact file size. No Unicode/emoji or raw
binary mode is implemented. Paging, styling, terminal width and table layouts are
inapplicable to generated bytes: stdout uses the same data in a TTY and a pipe.
Generation is noninteractive; cancellation can leave a partial file. Options do not
change with locale, and logging configuration follows the shared precedence above.
Only a literal `-` changes output routing; paths otherwise remain native paths.

There is no direct GNU/BSD counterpart, so port requirements P1–P4 are inapplicable.
U1/U2/U3/U4/U8/U9 have scoped [library](tests/library.rs), [CLI](tests/cli.rs), and
compiled API-example coverage; U5/U6 decisions are recorded above. This is not a
complete U1–U9 audit or a performance claim. U7 evidence is local macOS arm64;
Linux execution remains a CI check, not a local result. Other cases remain unaudited.
The Linux-only `/dev/full` regression checks buffered flush failure; local macOS
runs cannot execute it. Shared overhead evidence is [recorded separately](../utils/cli-tracing/overhead.md).
