# Sanctuary

- Sanctuary is a Cargo and uv workspace of Rust CLIs, shared libraries, and Python services.
- `buildins/` contains standalone CLIs; `packages/` contains applications and services; `utils/` contains shared libraries.
- `tools/` contains repository checks, benchmarks, and the CLI playground; `infra/` contains provisioning. Read each package's README for usage and limitations.
- **Branches and commits:** Follow [dev-new-branch](.agents/skills/dev-new-branch/SKILL.md); use `feat/`, `fix/`, `chore/`, `docs/`, or `refactor/`. Follow [gitmoji-commit](.agents/skills/gitmoji-commit/SKILL.md) for commits and PR titles.
- **Worktree setup:** Codex runs [environment setup](.codex/environments/environment.toml) automatically for new worktrees; for manually created worktrees, run `uv sync --all-packages && prek install && sh .codex/environments/link-rust-skills.sh` from the worktree root. Rust skills installed by `cargo agents sync` in the primary checkout are shared through symlinks; keep that checkout available and update skills there. Existing worktree skill directories are preserved.
- **One crate, one CLI:** Each CLI has its own directory and Cargo package with exactly one binary of the same name, using `src/main.rs`. Keep tests, docs, and benchmarks in that package; share code through libraries. Update links, lockfiles, and checks when moving packages.
- **Verification:** Follow [cli-testing](.agents/skills/cli-testing/SKILL.md) for required E2E coverage and independent reference fixtures. Run affected packages' and consumers' tests and linters directly; leave full validation to CI. Use the root uv workspace, lockfile, Ruff, and strict mypy configuration. Never run prek checks manually or bypass hooks; real commits run hooks. Monitor checks through execution sessions, never process lists or background logs. Isolate temporary Git repositories from inherited Git environment and global/system configuration; investigate unexpected bare status before changing configuration.
- **Benchmarks:** Use `tools/cli-bench/bench.py` for package-owned TOML suites with matching `binary` names; CI runs only for PRs whose CLI `src/**/*.rs` or `build.rs` changed from the merge base, without overrides or title/body-triggered reruns; one-sample runs are smoke checks, not evidence of performance changes.
- **Documentation:** Follow [clis-documentation-pipeline](.agents/skills/clis-documentation-pipeline/SKILL.md) for documentation ownership, layout, writing, and verification when creating, editing, or reviewing persistent documentation for human readers.
- **Security:** Read [the threat model](docs/thread-model.md) when changing input handling, authentication, sandboxing, persistence, CI publication, or infrastructure; update it when trust boundaries or deployment assumptions change.
