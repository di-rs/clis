## Purpose and accepted scope

Build an original Rust package at `tools/cli-bench` with a thin CLI and reusable
library. A contributor must be able to run a saved scenario against an external
reference, an earlier Rust revision, or both, and publish the exact procedure,
correctness results, raw measurements and readable comparisons in a PR.

PR 7 is research context only. Do not port its scripts, preserve its interfaces,
depend on its merge, or rework that PR as part of this implementation. Use distinct
new workflow names. Existing unrelated utility behavior and Kara remain outside
scope. Do not claim optimization gains from implementing the harness itself.

| ID | Requirement |
| --- | --- |
| R1 | Support reference/candidate, previous/candidate and reference/previous/candidate comparisons. |
| R2 | Build explicit Git revisions through Cargo and accept explicit prebuilt executable paths. |
| R3 | Biggie CLI generates every benchmark dataset; preserve generator identity, seed/pattern, argv, byte count and hash. |
| R4 | Check exact expected status, stdout, stderr and relevant filesystem effects before timing. |
| R5 | Measure elapsed time, declared throughput, executable bytes and separate process peak-RSS samples. |
| R6 | Preserve local evidence outside `target/`, 90-day PR artifacts, and permanent compact history for default-branch and explicitly promoted runs. |
| R7 | Produce terminal, JSON and Markdown reports; provide offline analysis, history listing and bundle export/replay. |
| R8 | Run advisory Linux/macOS Actions jobs and update one benchmark comment per PR; timing differences never fail a merge check. |
| R9 | Deliver Biggie, tailr and mkdirr suites, including real pipe input and mutation reset. |
| R10 | Keep typed operations independent of argv, global streams/state, process exit and logger initialization. |

First release: warm-cache measurements; no privileged cache eviction, TUI,
dashboard/service dependency, allocation/instruction/energy profiler, Windows
support, general-purpose shell scripting language, or migration of every utility.

## Fixed execution policy

These lines are also the implementation plan's global constraints.

- Implement from scratch under `tools/cli-bench`; PR 7 is reference only.
- Support native Linux and macOS; record evidence separately for each platform.
- All benchmark datasets are generated by Biggie CLI with explicit seed or literal pattern/schedule.
- Support Hyperfine 1.20.0 initially; reject other versions before timing.
- Full measurements use 3 checked warmups and 20 measured samples per role per batch, with forward and reverse batches.
- Peak RSS uses 5 fresh process samples per role/case, separate from elapsed-time samples.
- Smoke measurements use 1 warmup, 2 samples per role in each of two batches, and 1 RSS sample; label them smoke-only and suppress performance conclusions.
- Performance is advisory; schema, build, identity, correctness, timeout and execution failures return failure.
- Local evidence defaults to `.cli-bench/`; Cargo build caches remain under `target/cli-bench/`.
- PR artifacts request 90-day retention; durable compact history uses `chore/benchmark-history`.
- Default PR comparison is exact PR head versus its merge-base with the current target-branch SHA, resolved once per run.
- Default release builds use `--locked`, one selected toolchain, the same target/features/flags/strip policy, and isolated source/target directories.
- No first-party unsafe code, global cwd/environment mutation, implicit tool installation, destructive cache eviction or unrelated utility fixes.
- Rust unit tests live in `#[cfg(test)] mod tests` in the implementation's source file; `tests/` contains integration tests and their support files only.
- Freeze and identify the measurement contract, retain optimization attempts, and use separate Biggie confirmation workloads before claiming a gain.
- Serialize measurement sessions across cooperating harness processes on the host, including invocations using different data directories.

Full and smoke are named measurement profiles, not Cargo profiles. Reject any
other measurement profile in v1. A sample deadline defaults to 120 seconds; a
build deadline is 1,800 seconds. Record overrides and reasons when a suite changes
the deadline. Enforce 128 selected cases, 256 MiB per captured stream, 8 GiB total
generated inputs and 2 GiB run evidence by default. Reject excess with preserved
failure evidence; users may increase limits explicitly in the suite's limits table.

## CLI and Cargo relationship

Add `tools/cli-bench` explicitly to workspace members. Cargo builds the harness,
Biggie and selected utility revisions. Cargo execution and compilation are outside
measurement. `cargo bench` remains the separate entry point for library benchmarks.

The following interfaces are the implementation target, not working commands yet:

```sh
cargo build --locked --release -p cli-bench

# Saved suite names resolve from tools/cli-bench/suites/index.toml.
target/release/cli-bench run -s tailr -r HEAD -x "$GNU_TAIL"
target/release/cli-bench run -s tailr -r HEAD -b "$OLD_SHA"
target/release/cli-bench run -s tailr -r HEAD -b "$OLD_SHA" -x "$GNU_TAIL"

# Prebuilt paths avoid compilation; source provenance may be incomplete.
target/release/cli-bench run -s tailr -a "$NEW_TAILR" -p "$OLD_TAILR" -g "$BIGGIE"

target/release/cli-bench report -i "$RUN_DIR" -f markdown
target/release/cli-bench compare -i "$RUN_DIR" -b previous -a candidate -f json
target/release/cli-bench history -d .cli-bench/runs -s tailr -f json
target/release/cli-bench export -i "$RUN_DIR" -o "$BUNDLE_DIR" -I -B
target/release/cli-bench replay -i "$BUNDLE_DIR" -g "$BIGGIE"
```

| Command | Contract |
| --- | --- |
| `build` | `-p/--package`, `-r/--revision`, `-t/--toolchain`, `-F/--features`, `-N/--no-default-features`, `-d/--data-dir`; produce an immutable artifact record. |
| `check` | Same selection arguments as run; resolve/build/generate and execute all correctness gates, without timing/RSS. |
| `run` | Require candidate plus at least one comparator; save one complete run bundle. |
| `compare` | Select roles inside one saved run with `-i/--input`, `-b/--baseline`, `-a/--candidate`; compute offline results. It does not divide timings from unrelated runs. |
| `report` | Render a validated saved run; `-f/--format` is `terminal`, `json` or `markdown`. |
| `history` | List validated run/history records under `-d/--directory`, optionally filtered by `-s/--suite`; no network, implicit fetch or speedup across hosts. |
| `export` | Copy a portable evidence directory; optional `-I/--with-inputs`, `-B/--with-binaries`. Never overwrite an existing destination. |
| `replay` | Reconstruct a new run from the resolved bundle recipe, verifying identities/hashes; explicit replacement bindings are required for absent binaries. Preserve the old bundle. |

Run/check flags: `-s/--suite` ID or TOML path, repeatable `-c/--case`,
`-r/--candidate-ref` or `-a/--candidate`, `-b/--previous-ref` or `-p/--previous`,
`-x/--reference`, `-g/--biggie` or `-G/--generator-ref`, `-t/--toolchain`,
`-F/--features`, `-N/--no-default-features`, `-m/--measurement-profile`,
`-d/--data-dir`, `-M/--manifest-path`, `-f/--format` and `-H/--hyperfine`.
Optional `--experiment`, `--hypothesis` and `--change-summary` flags follow the
[experiment contract](2026-10-06-cli-bench-experiments.md#1-optional-experiment-metadata).
Reference paths are always explicit; never substitute native BSD tools for GNU.
Replay accepts the prebuilt role flags and reference/Biggie bindings, not arbitrary
new case parameters. Help/version use `-h/-V`; logging uses the shared `-L` setup.

Exit 0 means requested evidence was produced, even if the candidate is slower.
Exit 1 means operational/validation failure; exit 2 is invalid CLI input; handled
SIGINT exits 130 and SIGTERM exits 143 after cleanup. Missing RSS is represented
as unavailable and makes a requested full-metric run incomplete, not successful.
Report/export still work on a structurally valid incomplete bundle.

## Versioned suite contract

The approved [v1 schema](2026-10-06-cli-bench-suite-v1.md) defines the exact types,
defaults, profile overrides and validation rules.

Suite TOML, resolved-run JSON, result JSON and history JSON each carry
`schema_version = 1`. Reject unknown fields, duplicate IDs, invalid references,
NUL bytes, escaping scratch paths and unsupported versions before executing tools.
The suite is execution data, not a script. Accept UTF-8 argv and paths in v1;
reject unsupported non-UTF-8 invocation paths explicitly rather than lossy conversion.

| Suite field | Meaning |
| --- | --- |
| `id`, `package`, `binary` | Stable case family and exact Cargo targets. |
| `generator` | Repository revision pinned to a full SHA, package `biggie`, build feature policy; explicit CLI binding may replace it and is recorded. |
| `environment` | Child-only allowlisted settings, starting with `LC_ALL=C`, `TZ=UTC`, `CLIS_LOG_LEVEL=off`; isolated HOME/config directories. |
| `limits` | Explicit resource caps; defaults above. |
| `datasets` | Named Biggie argv, explicit seed/pattern, output file and independent shape assertions. |
| `cases` | Stable ID, purpose, argv by role, stdin/stdout policy, exact status, correctness rules, mutation setup, optional meaningful work numerator. |

Arguments are arrays of strings. Resolve only whole-argument tokens:
`@input:ID` is a generated dataset path; `@scratch:REL` is a contained scratch
path; `@records:ID` expands a Biggie-generated LF path list into contained argv
paths. `@@` escapes a literal leading `@`. Generation accepts exactly one
`@output` token per dataset in v1. No substring interpolation, environment expansion,
glob expansion or arbitrary setup shell command is allowed.

Role argv overrides permit different interfaces with equivalent work. Missing
role argv inherits the common argv array. An unsupported feature in an old revision
is a failed/inapplicable selected comparison with an explanation; it is never
silently dropped. `--case` lets users explicitly select the common supported subset.

Stdin modes: null, regular-file and pipe. Stdout modes: discard, drained-pipe and
scratch-file. Initial cases use explicit sink policies, never a hidden default.
Correctness captures bytes separately before measurement; it also checks the
declared sink during bounded validation when sink behavior affects semantics.
The v1 pipe workload measures a finite, fully consumed pipeline and requires
successful producer and consumer status. Intentional early consumer termination
and nonzero pipe outcomes are rejected as unsupported; exact nonzero direct
command outcomes are supported.

Correctness rules are closed enums: equality to every selected baseline or a named comparator, literal/hex
bytes, empty stderr, exact byte budget/pattern, record/text shape, and expected
directory-tree effects. Combine independent assertions with comparator equality.
Do not import GNU test code or embed an interpreter for custom validators.

## Evidence and storage

Each run records the harness executable hash/version, validator policy and analysis
policy alongside its resolved suite, generated input identities, measured work,
I/O boundaries and build settings. Together these identify the measurement
contract. An optimization experiment fixes that contract and its starting source
SHA. Changing a scenario, correctness rule or measured work starts a distinct
experiment; the report shows the changed contract and all selected binaries must
be rerun under it. Hashes expose changes but do not establish oracle correctness.

An optional experiment record retains a hypothesis, change summary and links to
every attempted run, including failures and attempts without an improvement.
Keep incomplete attempts visible. This record organizes evidence; it does not
edit code, select winners automatically or use an old timing as a new denominator.

```text
.cli-bench/                         # ignored; survives cargo clean
  artifacts/<identity>/           # immutable executable copy + build.json
  datasets/<recipe-hash>/          # Biggie outputs + generation.json
  runs/<unique-run-id>/
    suite.toml                    # exact submitted suite
    manifest.json                 # resolved roles, host, I/O, hashes, policy
    result.json                   # normalized observations and analysis
    publication.json              # bounded compact projection for CI/history
    report.md
    correctness/                  # raw streams/status/effect snapshots
    raw/timing/                   # per-sample Hyperfine JSON and diagnostics
    raw/rss/                      # native time output and status
    events.jsonl                  # transitions, warnings and failures
  history/                        # optional downloaded compact history
target/cli-bench/                  # disposable builds/scratch only
```

Use create-new directories and per-run locks; never reuse an existing run ID or
overwrite a frozen executable. Write files through temporary siblings and rename;
complete the run only after final identity checks and successful flush. Preserve
an incomplete status after interruption or I/O failure. A store operation failure
is never converted into an empty successful result. Export verifies every copied
hash and includes a manifest of contents; optional inputs/binaries are explicitly
listed as included or missing.

Run metadata includes exact source SHAs, lockfile and executable hashes, logical
bytes, build commands, compiler/Cargo identity, target/features/configuration,
relevant flags, reference version, Biggie identity/argv, input hashes/bytes, host
CPU/RAM/OS/filesystem information where available, inherited umask, relevant
environment, sample order, tools, cache/sink policy, limits and provenance gaps.
Do not dump secrets or unrestricted environment values. Hash user-level Cargo
configuration and record affected build settings without publishing credentials.

Executable hashes identify the file, not all dynamic dependencies or the kernel.
Record platform/reference package identity and disclose that limitation. A
prebuilt executable without a build record remains usable for a labelled product
comparison; the current `rustc -Vv` is never attributed to its unknown build.

Permanent history is compact data on `chore/benchmark-history`: per-run immutable
`runs/<run-id>.json` plus an index. Preserve scenario/resolved recipe, identities,
all normalized time/RSS samples, native compact resource values, checksums,
validation outcomes, tool warnings and policy version. Exclude binaries, generated
datasets and large stdout captures. Preserve links to expiring full artifacts and
their expiry. The history record alone supports offline analysis; it may require
rebuilding/regenerating resources for execution replay.

Automatically append default-branch full runs; maintainer-triggered promotion may
append a selected PR/manual run. PR runs otherwise retain 90-day artifacts and
their comment. History is append-only by run ID; identical repeated publication
is idempotent, conflicting content for an existing ID fails. No force-push,
rewriting old records or committing generated datasets to the default branch.

## Building and binding executable roles

Resolve refs through Git to commit SHAs before side effects. Build from isolated
detached worktrees/snapshots, never switch the user's checkout or stash work.
`HEAD` means the committed tree; if the working tree is dirty, say explicitly
that those edits are excluded and suggest prebuilt mode. Do not invent a dirty
working-tree build identity. Reject unsupported submodule/LFS inputs initially
with an actionable error instead of silently omitting source.

Resolve one toolchain for all Rust roles, record full compiler identity and verify
it before/after builds. A floating repository nightly may be used locally with
its exact observed hash recorded; CI resolves a dated toolchain once. Refuse a
compiler change during a run. Each revision keeps its own lockfile. Different
dependency versions are part of an implementation revision; they are recorded,
not automatically a comparability failure.

Build `--release --locked -p PACKAGE --bin BINARY` with distinct target directories.
Record build profile, target, requested/resolved features, Cargo configuration,
compiler/linker flags and stripping. Source-isolation comparisons require the same
build policy; configuration changes produce a product/build comparison with the
differences disclosed, never a source-isolated claim. Requested revision builds
still receive the same policy; explicit prebuilt bindings may differ. Unequal work
or incompatible measurement boundaries invalidate either comparison. Retain Cargo
JSON compiler-artifact and selected-package dependency
records. Do not guess output paths when Cargo identifies the executable.

Copy finished executables into `.cli-bench/artifacts`, record provenance and hash
again before/after measuring. Build-cache keys include source, toolchain, target,
lockfile, features and build policy; cached evidence is verified before reuse.
No silent compiler fallback, lockfile update or reference installation.

## Biggie data and correctness lifecycle

Bundled suites pin the fixture generator to
`0d8caa8387d446e91ef263c1ecab88870b735eb5`. A future suite revision may intentionally
change it; replay retains the old identity. The generator is independent of the
Biggie candidate under measurement. A caller-supplied `--biggie` is hashed and
recorded; replay requires the original hash unless the user starts a new experiment.

Generate outside timing. Validate shape independently with streaming code; retain
complete hashes and bytes. Seeds are not guarantees across generator upgrades or
platforms. On replay, a changed generated hash is failure, not an updated expected
fixture. The harness may materialize/reset directories, but content generation
always belongs to Biggie. Small hermetic unit-test fixtures are not benchmark data.

Before any selected case is timed, validate every selected role/case. Record all
failures; if any selected gate fails, start no timing. Record genuine nonzero exit
expectations rather than accepting any failure. Compare filesystem type/path sets,
relevant permission bits and file contents without following symlinks; omit dynamic
creation timestamps only where explicitly irrelevant. No broad output normalization.

Reset mutating cases before each validation, warmup, time sample and RSS sample.
Limit reset to harness-owned, marked scratch directories. Refuse escaped paths and
symlink replacements; verify the initial state after reset. Check mutation effects
again after each measured invocation. Read-only cases receive a final correctness
pass and input/binary hash check before their results become complete.

## Timing and resource execution

Hold a cross-process measurement lock throughout warmups, timing, RSS sampling and
final checks. The lock is shared across cooperating harness invocations even when
they use different evidence directories. Release it on success, failure and
process death. Test contention with real child processes. This control cannot
exclude unrelated workloads or establish that a host is idle. Use the approved per-user host lock across repositories/data directories,
acquired before preparation and held through final validation. Contending runs
wait cancellably; offline report/history/export remain available. See the
[coordination contract](2026-10-06-cli-bench-experiments.md#2-cooperating-process-lock).

The sample driver owns scheduling and process groups. Library callers supply a
cancellation token; only the CLI installs SIGINT/SIGTERM handling. Use safe Unix
process-group APIs, terminate the owned group on timeout/cancellation, wait for
children and finish evidence. This controls cooperative command trees, not malicious
processes deliberately escaping their group; the harness is not an OS sandbox.

For each case, run a forward batch (`reference`, `previous`, `candidate`, omitting
absent roles) and its reverse. Each role starts with 3 directly executed, checked
warmups, followed by 20 individually controlled Hyperfine observations. Invoke
Hyperfine with `--runs 1 --warmup 0 --shell=none`, explicit input/output policy,
and a unique JSON path per observation. Hyperfine's own startup is outside its
reported command time. This costs extra controller processes but provides a
bounded sample, exact scheduling and reset boundary without adding a supervisor
inside the timed command. Preserve all engine warnings; a one-sample engine
summary is not the overall analysis.

For a direct expected nonzero status E, pass only `--ignore-failure=E` and require
the single exported exit code to equal E. Zero, signal termination, missing/null
status and any other code invalidate the sample. Warmups are checked by our runner,
so Hyperfine's discarded warmup status cannot hide a mismatch. No blanket `-i`.

Round-trip quote argv through the engine's documented string parser. For the
declared pipe workload, invoke a fixed Bash pipeline through direct Hyperfine mode:
an identified `cat` feeds the already generated input to the target; `pipefail`
requires both commands to succeed. Supply paths/arguments as positional parameters,
never interpolated source. Record Bash/cat identities. Its time includes pipeline
shell/producer overhead and is labelled `pipeline`, not isolated CLI startup.
Direct cases remain free of that shell. Warmups/checks use the same boundary.

Size is the retained executable's metadata byte count, not allocated blocks or
compressed size. RSS uses identified `/usr/bin/time`: GNU `-v` with a separate
resource file on Linux; `-l` on macOS with preserved native stderr. Parse GNU
maximum RSS in KiB and Darwin maximum RSS in bytes, retaining raw units. Validate
status and the diagnostic prefix independently of the resource trailer. Missing,
duplicate, malformed or negative measurements are errors/unavailable, never zero.
Use the same invocation boundary for RSS as time; pipeline RSS is OS command
accounting, not the sum of simultaneous process memory. Do not compare unlike
scopes or present it as total pipeline memory.

## Analysis and reporting

Analysis policy `descriptive-v1` is deterministic over stored samples. Report each
batch's mean, median, sample standard deviation, min/max/count; the overall mean
and median across equally sized batches; and candidate/baseline elapsed ratios
and absolute/percentage changes. Show executable-size absolute/percentage change
and RSS median/range separately. Throughput is `declared_work / elapsed_seconds`;
seek-tail cases have no whole-file throughput claim.

Mark opposing batch directions inconclusive. Consistent direction is an observation,
not statistical significance or proof of equivalence. Do not add a hidden regression
threshold or discard outliers. Distinguish wrong output, unsupported, unavailable,
incomplete, smoke-only and valid observational evidence. Zero/nonfinite timings,
mixed units, altered dataset hashes and unmatched scopes cannot produce a ratio.
Historical runs are listed by suite/commit/platform; time ratios require roles
measured in the same run. Report no confidence interval until a reviewed policy
implements one.

Reports show purpose, roles/build identity, correctness, both comparison ratios,
metrics/units/sample counts, batch direction, scope/limitations, exact replay
recipe and artifact retention. Terminal output is plain and width-tolerant when
redirected; optional color obeys terminal detection and `NO_COLOR`. No pager or
interactive prompt. JSON/Markdown stdout contains data only; logs/errors go to
stderr and writers/flush failures propagate.

## Initial suites

| Suite | Full workloads | Independent checks and boundaries |
| --- | --- | --- |
| Biggie | Seeded text: 100,000 lines, 4 words of 8 ASCII characters, seed 42; records: `miss`, `Hit`, empty, repeat 2, 10,000 cycles; bytes: 16 MiB, pattern `00ff1b0d0a` | 3,600,000 text bytes/shape, exact 200,000 record bytes/pattern, exact byte budget/repeating pattern. stdout is drained pipe; previous/candidate comparison only. |
| tailr | Biggie text: 1,000,000 lines with the same fixed word shape; last 10 lines from file, last 1,000 bytes from file, last 10 lines from pipe; tiny two-record startup | GNU equality and explicit expected slices computed from the generated input. File and pipeline cases are separate; no fake scan throughput. |
| mkdirr | Biggie records generates `a/b`, `c/d`, `e/f`, `g/h`; create these absent paths with `mkdir -p`/mkdirr; separate existing-path case | Exact tree/type set and mode comparison, empty stdout/stderr, status 0. Reset absent/existing state before every invocation; directory operations reported, not byte throughput. |

Smoke uses 1,000 text lines, 100 record cycles and 64 KiB bytes; the tiny and mkdir
shapes remain unchanged. These sizes are encoded in the suite's named profile
sections and hashes; never silently compare smoke with full. Unsupported historical
Biggie shapes require selecting the shared text case explicitly. Identical binaries
can prove wiring but never establish an optimization.

Maintain a separately identified confirmation case set using Biggie recipes with
different seeds, sizes and boundary shapes. After tuning, rerun the fixed baseline
and final candidate on those cases with full measurement settings. Record all
confirmation outcomes, including correctness failures or regressions. Smoke is a
wiring check and never substitutes for confirmation. The [confirmation recipes](2026-10-06-cli-bench-experiments.md#3-separately-named-confirmation-cases)
use `confirm-*` case IDs and the existing repeatable `--case` selector.

## Actions and permanent history

Create independent `cli-bench.yml` and `cli-bench-publish.yml` workflows. The first
supports PR, default-branch push, manual and reusable `workflow_call` execution.
It runs package tests plus smoke on Linux/macOS, builds roles before full measurement,
and uploads evidence/summary even when validation fails. Full runs use a quiet
single measurement job per OS and report shared-runner limitations. No CPU affinity
or power controls are claimed unless actually recorded. An explicit job timeout
and disk quota bound each job.

The PR checkout/manifest uses the exact head SHA; resolve its merge-base against
the target SHA, not `HEAD^` or a synthetic merge commit. Default-branch push uses
the candidate's first parent as previous; no parent is a recorded unavailable
comparison. Generator selection stays independent. Standard fork approval policy
applies; measurement has read-only contents permission, no secrets and no persisted
Git credentials. Use SHA-pinned actions and identified GNU/Hyperfine installs.

`cli-bench-publish.yml` runs trusted default-branch publisher code on `workflow_run`
and explicit maintainer promotion. Python 3.14 standard-library code, with uv-managed
Python and project configuration, is required for the small GitHub publisher; the measurement/library implementation remains Rust.
Separate jobs give the comment publisher only comment permissions and the history
publisher only contents-write permission. Neither executes PR checkout content,
artifacts, replay recipes or downloaded binaries. No `pull_request_target` job
builds PR code.

Download only the triggering workflow's named publication artifacts. Bound compressed
and expanded size, reject path traversal/symlinks/duplicate members, and accept one
versioned JSON publication record per platform, maximum 16 MiB each. Validate
repository/run/workflow identity through GitHub API data and bind candidate SHAs to
the actual PR/default-branch commit. Derive PR association from trusted run/API
metadata; never trust an artifact's PR number or URL. Missing/ambiguous association
leaves a job summary/artifact and an explicit publishing error. Recheck current PR
head before updating the marked comment; stale runs cannot replace newer evidence.
Serialize updates per PR and retain API-verified workflow run number/attempt in
comment metadata. Compare that ordering before writing so an older run or attempt
of the same head cannot replace a newer report.

Generate Markdown from bounded typed data with escaped text and API-derived links.
The marker is `<!-- cli-bench:v1 -->`; update only this bot-owned comment. Aggregate
Linux/macOS under it without combining measurements. No comment spam, arbitrary
HTML/links or token/environment logging. Validate failures too: a wrong-output
benchmark should produce a clear failure report when its artifact is available.
Cap the rendered comment at 60,000 UTF-8 bytes; when rows exceed that budget,
include an explicit omission count and API-derived full-evidence link.

History appends use Git data operations without checking out the data branch,
with non-force updates and optimistic conflict retry. Serialize publisher updates
per repository and reject an existing run ID with different content. Automatic
history accepts default-branch full runs (including recorded failed runs with no
valid ratio); smoke and PR runs require explicit promotion. Record promotion's
source run and actor. Workflows on the default branch do not trigger recursively
from the history branch. Expired/missing artifacts are explicit promotion errors.

## Verification and rollout

Follow the repository [test conventions](../../../CONTRIBUTING.md#test-conventions).
Parser, validator, scheduler, statistics and resource-parser unit tests belong in
their respective `src/*.rs` modules. `tests/library.rs` covers public API consumer
workflows, `tests/cli.rs` covers CLI behavior, and `tests/process.rs` covers real
subprocess lifecycle integration. `tests/common/mod.rs` contains shared integration
helpers only. Neither `tests/library.rs` nor `src/lib.rs` collects other modules'
unit tests. Python publisher tests remain beside `publish.py` under `ci/`.

Ordinary tests are hermetic: fake child tools, tiny explicit test fixtures, saved
Hyperfine/native-time output, no reference installs/network/real speed thresholds.
Test direct library calls twice in one process, invalid options, failing writers,
path boundaries, process descendants, checked nonzero exits, resets, tampering,
atomic storage, offline statistics, export/replay and publisher abuse cases.

Native integration separately builds Biggie and the three utilities, installs
identified references/Hyperfine in CI, runs smoke and full evidence, and verifies
report regeneration. Compare file stdin versus true pipe behavior with a probe;
exercise absent/existing mkdir state each iteration. Size/RSS outcomes must identify
the measured executable and platform. No synthetic timing fixture is performance
evidence.

Follow package then workspace checks in CONTRIBUTING, public API docs/examples,
Python publisher tests, actionlint and zizmor. Validate actual Actions runs after
default-branch registration; before that label remote execution unverified. A
workflow definition passing lint is not a successful publication/history trial.
Test comment update/stale suppression, a default-branch history append and repeat
publication idempotence. Do not modify repository merge rules to enforce timing.

Acceptance requires all R1–R10 implemented, the three suites executable locally
and through the workflow, two comparison modes demonstrated with declared identity,
and evidence/history/reporting checks passing. Native platform or remote permission
limits remain explicit outstanding acceptance items, not silently completed work.
