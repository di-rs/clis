# CLI Benchmark Harness Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task, as selected by the maintainer. Steps use checkbox (`- [ ]`) syntax for tracking. Implementation is authorized. Ask the maintainer for a decision on unresolved questions, conflicts or unexpected problems; do not resolve them by assumption.

**Goal:** Deliver a reusable CLI benchmark system with checked reference/revision comparisons, Biggie datasets, replayable evidence, permanent compact history and advisory PR reports.

**Architecture:** Implement an original Rust library and CLI at `tools/cli-bench`. The library owns scenarios, builds, validation, process lifecycle, sample scheduling, storage and offline analysis; Hyperfine owns elapsed measurement. Independent GitHub workflows run benchmarks with read-only permissions and use trusted publication code for comments/history.

**Tech Stack:** Workspace Rust nightly, Clap/shared diagnostics, Serde/JSON/TOML, SHA-256, tempfile, safe rustix process APIs, signal-hook, shell-words; Hyperfine 1.20.0; GNU/macOS time; Biggie; Python 3.14 standard library for the small CI publisher, with uv-managed Python and project configuration for reproducible local and CI execution; GitHub Actions.

**Spec:** [CLI benchmark harness design](../specs/2026-10-06-cli-bench-design.md), including the approved [experiment/confirmation contract](../specs/2026-10-06-cli-bench-experiments.md). Read it and the [research](../../research/2026-10-06-cli-bench.md) before implementing. Base checkout at planning: `0d8caa8387d446e91ef263c1ecab88870b735eb5`.

## Global Constraints

- Implement from scratch under `tools/cli-bench`; PR 7 is reference only.
- Support native Linux and macOS; record evidence separately for each platform.
- All benchmark datasets are generated by Biggie CLI with explicit seed or literal pattern/schedule.
- Support Hyperfine 1.20.0 initially; reject other versions before timing.
- Full measurements use 3 checked warmups and 20 measured samples per role per batch, with forward and reverse batches.
- Peak RSS uses 5 fresh process samples per role/case, separate from elapsed-time samples.
- Smoke measurements use 1 warmup, 2 samples per role in each of two batches, and 1 RSS sample; label them smoke-only and suppress performance conclusions.
- Performance is advisory; schema, build, identity, correctness, timeout and execution failures return failure.
- Local evidence defaults to `.cli-bench/`; Cargo build caches remain under `target/cli-bench/`.
- PR artifacts request 90-day retention; durable compact history uses `chore/benchmark-history`.
- Default PR comparison is exact PR head versus its merge-base with the current target-branch SHA, resolved once per run.
- Default release builds use `--locked`, one selected toolchain, the same target/features/flags/strip policy, and isolated source/target directories.
- No first-party unsafe code, global cwd/environment mutation, implicit tool installation, destructive cache eviction or unrelated utility fixes.
- Rust unit tests live in `#[cfg(test)] mod tests` in the implementation's source file; `tests/` contains integration tests and their support files only.
- Freeze and identify the measurement contract, retain optimization attempts, and use separate Biggie confirmation workloads before claiming a gain.
- Serialize measurement sessions across cooperating harness processes on the host, including invocations using different data directories.

No TUI, custom timing engine, dashboard, generic shell execution language, cold-cache
control or optional CPU/allocation profiler is included. PR 7 will be reworked
separately after this system exists; do not add compatibility wrappers or depend
on its scripts/workflows landing first.

TUI, dashboard and generic shell execution support are tracked as follow-up
[#10](https://github.com/di-rs/clis/issues/10), after the initial harness release.

## Review Focus

1. A valid nonzero workload occasionally returns zero: reject it during warmup or measurement rather than silently accepting both statuses. Owned by Tasks 3, 6 and 7.
2. A timeout leaves a producer/grandchild alive or mutation reset hits a symlink outside scratch: terminate owned groups and reject escaped cleanup. Owned by Tasks 3 and 6.
3. A cached binary/data file changes, or a ref moves between resolution and build: preserve resolved identities and reject tampered evidence. Owned by Tasks 2, 4 and 5.
4. A delayed/forked PR artifact impersonates another PR, injects Markdown, or overwrites a newer comment/history record: validate API association and treat artifacts only as bounded data. Owned by Tasks 12 and 13.
5. Local evidence disappears during cargo clean, or replay silently regenerates different seeded bytes: store outside target and enforce exported identity/hash requirements. Owned by Tasks 2 and 10.
6. Concurrent harnesses contaminate measurements, a changed validator masquerades as the same experiment, or only successful attempts survive: verify cross-process exclusion, contract identity and complete attempt records. Owned by Tasks 2, 7–10 and 14.

as empty scaffolding. Follow the [test conventions](../../../CONTRIBUTING.md#test-conventions):
all Rust unit tests live in a `#[cfg(test)] mod tests` in the source file owning
